# Итерация 9: установка без лишних вопросов и без битого пути

## Context

Две вещи по итогам прогона.

**Установка форка поверх спрашивает токен и ID чата**, хотя человек ставит
форк, а не бота. Это лишний вопрос в неподходящий момент: у бота автора при
первой установке спрашивают «Установить телеграм-бота? [y/N]» с умолчанием
«нет» (`lib/install.sh:316`, `offer_tgbot_install`), а токен — только у тех,
кто согласился. Наш установщик так не делает.

**Из панели установка сторожа падает** с `sh: 0: cannot open
/opt/mtproxyl-alertbot/install-alertbot.sh: No such file`. Панель зовёт
установщик по этому пути, а файла нет. Причина: копию кладёт только
`install-alertbot.sh` (строки 217-223), а установка из меню MTProxyL —
`alertbot_install` в `lib/alertbot.sh` — не кладёт её вовсе. Кто ставил
сторожа из меню, остался без файла, и панель об этом узнала самым неудачным
образом: сырым сообщением от `sh`.

Плюс сама ветка «скрипт пришёл по трубе» в `install-alertbot.sh` глушит
неудачу скачивания через `|| true` — то есть копия может не появиться и там,
молча.

## Решения

| Вопрос | Решение |
|---|---|
| Вопросы при установке форка | Как у бота автора: молча обновляем установленного, иначе один вопрос [y/N], токен — только при согласии |
| Копия установщика | Кладут все пути установки, включая меню; неудача скачивания больше не глотается |
| Панель без файла | Не сырая ошибка от `sh`, а понятный текст и запасной путь через CLI |

## Что меняется

### 1. `install-fork.sh` — вопросы только по делу

Блок «3. Бот-сторож» получает три ветки:

- **сторож уже установлен** — переустановка молча, токен берётся из его же
  конфига (так и сейчас, вопросов нет);
- **не установлен, токен передан флагами** — ставим сразу;
- **не установлен, флагов нет** — спрашиваем «Установить бота-сторожа?
  [y/N]» с умолчанием «нет», ровно как `offer_tgbot_install`; при согласии
  установщик сам спросит токен и чат, при отказе — печатаем, что поставить
  можно позже из панели или пунктом меню.

Без терминала (cron, чужой скрипт) вопрос не задаётся — считаем отказом.

### 2. Копия установщика кладётся всегда

- `lib/alertbot.sh`, `alertbot_install` и `alertbot_update`: после установки
  бинарника кладут `install-alertbot.sh` в каталог бота, скачивая его из того
  же релиза/ветки, что и сам бинарник. Сейчас этого нет вовсе — отсюда и
  поломка.
- `install-alertbot.sh`: ветка «пришёл по трубе» перестаёт глушить ошибку
  `curl` — если копию положить не удалось, установщик говорит об этом вслух.
  Установка при этом не срывается: бот работает и без копии, страдает только
  управление из панели.

### 3. Панель переживает отсутствие файла

`internal/mtproxylctl/alertbot.go`: перед запуском установщика панель
проверяет, есть ли он (`sudo test -f`), и если нет —

- пробует `mtproxyl alertbot install` (на форке подкоманда есть);
- если и её нет, отвечает человеческим текстом: установщик не найден,
  обновите форк либо выполните `curl … | sudo sh` — с готовой командой.

Сырое `sh: 0: cannot open …` человеку не говорит ничего.

Права sudo для панели пополняются вариантом `/usr/bin/sh` рядом с `/bin/sh`:
на части систем `sh` лежит там, и правило бы не совпало.

## Проверка

Как в CI: `gofmt -l`, `go vet`, `golangci-lint run`, `go test -race ./...` в
обоих модулях, `npm run build`, `sh -n`/`bash -n` по всем скриптам.

На ноде:
1. `install-fork.sh` при установленном стороже — ни одного вопроса, бот
   обновляется и перезапускается.
2. Он же на машине без сторожа — один вопрос [y/N]; отказ ничего не ломает и
   печатает, как поставить позже.
3. Кнопка «Переустановить» в панели работает, а на машине, где установщика
   нет, показывает понятный текст вместо ошибки `sh`.
4. После установки из меню MTProxyL файл `/opt/mtproxyl-alertbot/install-alertbot.sh`
   на месте — панель им пользуется.
