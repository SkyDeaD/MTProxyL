# Итерация 10: панель ставит бота сама, обратная связь на месте, короткие заметки

## Context

Разбор показал, что дело не в мелких ошибках, а в неверной схеме.

**Панель не может поставить бота с нуля — по построению.** Она умеет только
запускать `/opt/mtproxyl-alertbot/install-alertbot.sh`, а этот файл кладёт сам
установщик бота. То есть чтобы поставить бота из панели, надо сначала
поставить бота. Пользователь отказался от установки при обновлении форка — и
кнопка в панели упёрлась в собственную предпосылку. Прошлая правка сделала
сообщение вежливым, но саму невозможность не убрала.

**Обратная связи в панели нет.** Нажатие «Установить бота» отдаёт 202 с
объектом операции, и страница обязана начать опрос — так делает карточка
бота-администратора (`TgbotPage.tsx:99`, `start(await tgbotApi.install(...))`).
Карточка сторожа результат выбрасывает (`AlertbotPage.tsx:231`): опрос не
запускается, колбэк перезагрузки не срабатывает, кнопка не блокируется. Со
стороны выглядит, будто нажатие ничего не сделало, а ошибка всплывает только
после F5. Плюс в словаре названий операций нет `alertbot:install`, поэтому
человек видит сырое «alertbot:install — ошибка».

**Заметки к релизу заросли** историей правок за неделю и автосписком коммитов.

## Решения

| Вопрос | Решение |
|---|---|
| Установка из панели | Через CLI MTProxyL, как у бота автора: `mtproxyl alertbot install` |
| Если подкоманды нет | Запасной путь — установщик на диске, затем понятное сообщение |
| Обратная связь | Карточка сторожа запускает опрос операции и блокирует кнопку, как карточка бота автора |
| Заметки | Только что даёт форк и как ставить |

## Что меняется

### 1. Панель ставит бота через CLI — `internal/mtproxylctl/alertbot.go`

Порядок попыток в `AlertbotInstall` (и так же для update/uninstall):

1. `mtproxyl alertbot install --token … --chat …` — работает всегда, когда
   стоит форк скрипта, и не требует, чтобы бот уже был установлен. Ровно то
   же самое панель делает с ботом автора (`tgbot install`), так что схема не
   новая, а приведённая к общей.
2. Если подкоманда неизвестна (панель форка на официальном MTProxyL) —
   прежний путь через `install-alertbot.sh`, если он на диске.
3. Если нет и его — сообщение с готовой командой, как сейчас.

В `mtproxyl-panel/install.sh` добавляются правила sudo на `alertbot
install|update|uninstall|status|set|use` — по образцу существующих правил для
`tgbot` (`install.sh:572-590`).

Эта же перестановка убирает разнобой: статус, настройки и активацию панель уже
берёт у бота напрямую, а установку — у CLI, и оба пути перестают зависеть от
того, лежит ли на диске конкретный файл.

Вариант «встроить установщик в бинарник панели и выкладывать его на диск»
отвергнут: `go:embed` не берёт файлы выше каталога пакета, а `install-alertbot.sh`
лежит в корне репозитория — пришлось бы держать вторую копию и сторожить её
тестом на совпадение. Ради случая, который и так покрыт третьей ступенью, это
лишняя механика.

### 2. Обратная связь — `frontend/src/pages/AlertbotPage.tsx`

- Ответ установки уходит в `start(...)` — тогда хук начинает опрос раз в две
  секунды и по завершении сам перечитывает статус.
- Из хука берётся `running`, кнопка блокируется на время установки.
- `load` перестаёт игнорировать поле `operation` из ответа статуса: после
  перезагрузки страницы видно, что операция идёт.
- В `OPERATION_LABELS` (`components/OperationProgress.tsx`) добавляются
  `alertbot:install`, `alertbot:service`, `alertbot:uninstall` — вместо сырых
  имён человек видит «Установка бота-сторожа».

### 3. Заметки к релизу — `mtproxyl-panel/RELEASE_NOTES.md`

Переписываются целиком: что делает форк, две команды установки, что умеет
бот, где выбирать между ботами. Без истории правок. В релизном workflow
отключается `generate_release_notes`, который добавлял автосписок коммитов.

## Проверка

Как в CI: `gofmt -l`, `go vet`, `golangci-lint run`, `go test -race ./...` в
обоих модулях, `npm run build`, `sh -n`/`bash -n` по скриптам.

На ноде — ровно тот сценарий, который сломался:
1. Форк стоит, бота нет. В панели ввести токен и ID, нажать «Установить
   бота» — видно спиннер с названием операции и живым выводом, кнопка
   заблокирована, по завершении карточка сама показывает «Работает».
2. Карточка «Активный бот» после установки показывает сторожа активным без
   перезагрузки страницы.
3. Кнопки «Обновить бота» и «Удалить» работают там же.
4. В релизе — короткие заметки без списка коммитов.
