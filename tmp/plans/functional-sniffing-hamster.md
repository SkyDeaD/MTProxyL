# Итерация 8: перезапуск сторожа, честный переключатель и порядок в релизах

## Context

Три вещи по итогам прогона `tg14`.

**Сообщение в чате осталось старого вида** — разделы вперемешку, таблицы
слиплись («Трафик 42.8 ГБTLS handshake»), зонды в самом низу, строка
«наблюдение раз в 1 мин» вместо «опрос». Всё это чинилось ещё в `tg13`, значит
на сервере работает прежний бинарник. Причина найдена и она ровно та, которую
неделю назад чинили в установщике панели: `install-alertbot.sh:269` делает
`systemctl enable --now`, а `--now` на **уже активной** службе — это `start`, то
есть пустышка. Файл на диске подменён, а в памяти остался прежний процесс. Та
же ошибка во втором месте — `lib/alertbot.sh:339`, установка из меню и панели.

**Переключатель в панели выглядит как две независимые вкладки.** Ощущение, что
можно включить оба бота сразу, хотя работать может только один. Сами вкладки —
это выбор, чью карточку показать, и ничего не переключают; настоящая активация
спрятана в кнопку «Сделать активным» внутри карточки.

**Релизов накопилось четырнадцать.** Каждая мелкая правка плодит новый тег, а
разобраться в списке уже нельзя.

## Решения

| Вопрос | Решение |
|---|---|
| Служба сторожа | `enable` + `restart` вместо `enable --now`: подменённый бинарник должен попасть в память |
| Переключатель | Карточка «Активный бот» сверху с двумя вариантами; ниже — карточки обоих ботов подряд, без вкладок |
| Релизы | Один скользящий тег для тестовых сборок, старые удаляются |

## Что меняется

### 1. Перезапуск службы сторожа

`install-alertbot.sh` и `lib/alertbot.sh`: `systemctl enable` отдельно, затем
`systemctl restart`. При первой установке результат тот же, при повторной —
единственный способ подменить работающий процесс. Ровно та же правка, что
недавно сделана в `mtproxyl-panel/install.sh`.

Заодно установщик печатает версию установленного бота (`mtproxyl-alertbot
--version`) — тогда «обновилось или нет» видно сразу, а не по формату
сообщения в чате.

### 2. Панель: карточка «Активный бот» — `mtproxyl-panel/frontend/src/pages/`

Вкладки убираются. Сверху страницы — карточка выбора, ниже подряд карточки
обоих ботов, каждая со своим состоянием и действиями.

```
┌ Активный бот ─────────────────────────────┐
│  ○ Бот-администратор      не установлен   │
│  ● Бот-сторож             работает        │
│                                           │
│  Работать может только один: включение    │
│  одного останавливает другого.            │
└───────────────────────────────────────────┘

[ Бот-администратор — состояние, установка, настройки ]
[ Бот-сторож — состояние, установка, настройки ]
```

Выбор неактивного варианта спрашивает подтверждение (`ConfirmDialog`, он в
проекте уже есть) и зовёт существующие ручки `POST /api/tgbot/activate` и
`POST /api/alertbot/activate`. Вариант, который не установлен, выбрать нельзя —
строка показывает «не установлен» и остаётся неактивной.

Образец, которому следуем, — `src/pages/ModePage.tsx`: там ровно такой же
выбор из двух взаимоисключающих режимов (активный подсвечен, у неактивного
кнопка «Переключить»), с подтверждением перед сменой.

`TgbotPage` становится страницей-контейнером: грузит оба статуса, отдаёт их в
карточку выбора и в обе карточки ботов. Содержимое карточек не меняется —
переезжает как есть.

### 3. Релизы: один скользящий тег

Тестовые сборки публикуются под тегом `mtproxyl-panel-v1.0.8-test`: новая
сборка перемещает тег и перезаписывает ассеты и заметки. Всё, что скачивает
бинарники, уже берёт либо `releases/latest`, либо самый свежий тег с префиксом
— то есть менять код установщиков не придётся.

Старые `-tgN` удаляются вместе с тегами (`gh release delete --cleanup-tag`).
Останется один релиз, и в нём всегда актуальная сборка.

Цена, которую принимаем осознанно: откатиться на предыдущую тестовую сборку
через релизы будет нельзя. Для боевых версий это было бы неприемлемо, для
тестовых — нет: код всегда можно собрать из ветки заново.

## Проверка

Как в CI: `gofmt -l`, `go vet`, `golangci-lint run`, `go test -race ./...` в
обоих модулях, `npm run build`, `sh -n`/`bash -n` по всем скриптам.

На ноде:
1. Обновиться и убедиться, что установщик печатает версию бота, а сообщение в
   чате пришло нового вида: разделы «Зонды», «Связь с Telegram», «Нагрузка»
   по порядку, таблицы не слиплись.
2. В панели — карточка «Активный бот»: выбор неактивного спрашивает
   подтверждение, после переключения одна служба поднялась, другая
   остановлена, и это видно в обеих карточках.
3. `systemctl is-enabled` после переключения указывает на выбранного бота.
4. В списке релизов форка — один тег.
