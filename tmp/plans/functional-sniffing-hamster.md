# Итерация 4: чистый чат, читаемые таблицы и починка статистики

## Context

Итерации 1–3 работают на боевом сервере. Прогон сборки `tg5` дал пять
замечаний, и одно из них вскрыло настоящую поломку, а не вопрос вкуса.

**Чат замусоривается.** Каждое нажатие кнопки клавиатуры («📊 Статус»,
«🔄 Проверить», «🔕 Пауза») остаётся в истории отдельным сообщением, и
служебные ответы бота тоже копятся. Принцип «одно сообщение в чате», ради
которого всё затевалось, размывается: сверху накапливается лента из
«Статус», «Проверить», справок и подтверждений.

**Дата-центры оформлены хуже зондов.** Строки вида
`✅ DC -203: 35 мс   ✅ DC -5: 225 мс` печатаются обычным текстом по два в
ряд, поэтому колонки разъезжаются: «DC 1» и «DC -203» разной ширины. Рядом
таблица зондов, где всё выровнено, — контраст бросается в глаза.

**Шапка кодового блока говорит «копировать».** Это подпись Telegram по
умолчанию. У блока можно задать имя, и «Зонды» там уместнее.

**Строка со строчной буквы.** «активных IP 83 · трафик 71.7 ГБ» — предложение
начинается со строчной, соседние строки с заглавной.

**Из статистики доехали только два числа — и это баг.** В сообщении есть
активные IP и трафик, но нет ни соединений, ни ошибок по классам, ни сбоев
рукопожатия, ни числа пользователей, ни версии движка, ни аптайма. Причина
найдена в коде, см. ниже, — и она же означает, что **оповещение о
перезапуске движка сейчас не работает вовсе**.

## Найденная поломка — почему статистика пустая

Две причины, обе в `internal/uplink`.

**1. Имя поля. Доказано.** Движок отдаёт классы ошибок как
`{"class":"timeout","total":4487}` — так их читает панель
(`frontend/src/components/ConnectionErrors.tsx:3-6`). Наш Go-тип ждёт
`count`:

```go
// internal/uplink/types.go:84-87
type ClassCount struct {
    Class string `json:"class"`
    Count int64  `json:"count"`   // движок отдаёт "total"
}
```

Отсюда нули во всех классах и пропавшая строка «Сбои рукопожатия»: она
скрыта условием `if u.HandshakeFails > 0` (`format.go:245`).

**2. Разбор по принципу «всё или ничего» плюс тихое проглатывание ошибки.**
`client.go` разбирает ответ одним `json.Unmarshal`, поэтому одно поле
неверного типа роняет весь объект. А `watcher.go` результат просто
выбрасывает:

```go
if sum, err := w.client.Summary(ctx); err == nil { ... }    // watcher.go:163
if info, err := w.client.SystemInfo(ctx); err == nil { ... } // watcher.go:184
```

Ошибка не пишется никуда. Сломались ровно два ответа — `Summary` и
`SystemInfo`, — а `Health`, `Users`, `MeQuality`, `UpstreamQuality`
отработали. Единственное поле, которое есть в обеих сломанных структурах и
отсутствует во всех рабочих, — `uptime_seconds`, объявленное у нас как
`int64`. Если движок отдаёт его дробным (`83220.47`), `encoding/json`
возвращает ошибку типа и выбрасывает **весь** объект. Панель этого не
замечает по построению: у неё `Record<string, unknown>` и `Math.floor`.

Это сильная гипотеза, но не доказательство — доступа к боевому серверу у
меня нет. Поэтому чиню так, чтобы починка **от гипотезы не зависела**:
устойчивый разбор + видимая ошибка + совместимость с обоими именами поля.
Заодно прошу снять с ноды сырой ответ движка, чтобы закрыть вопрос:

```sh
curl -s localhost:8888/v1/stats/summary | head -c 600; echo
curl -s localhost:8888/v1/system/info
```

(порт и заголовок авторизации — те же, что в `[telemt]` из
`/etc/mtproxyl-panel/config.toml`).

**Почему не поймали тестами.** В `internal/uplink/watcher_test.go`
подставной движок отвечает только на `/v1/health` и `/v1/system/info`;
`/v1/stats/summary` и `/v1/users` не заглушены ни в одном тесте, а
`st.Connections`, `st.Users`, `st.ActiveIPs`, `st.TopBadClasses` не
проверяются нигде.

## Решения

| Вопрос | Решение |
|---|---|
| Нажатия кнопок и команды | Удаляются сразу после обработки — Bot API это разрешает в личных чатах |
| Служебные ответы бота | Один слот: приходит новый — прежний удаляется; слот чистится и при переезде статуса |
| Ответ на `/start` | Не удаляется автоматически — он носитель reply-клавиатуры (обоснование ниже) |
| Дата-центры | Моноширинная таблица `DC · RTT · Писатели · Покрытие`, как в панели |
| Статистика | Полностью, как на дашборде: 6 показателей таблицей + все классы ошибок и сбоев |
| Подпись блоков | `<pre><code class="language-Зонды">` вместо безымянного «копировать» |
| Разбор телеметрии | Пополевой: кривое поле теряет себя, а не весь ответ; ошибка — в лог один раз |

### Почему ответ на `/start` остаётся

Документация Telegram **нигде не говорит**, что происходит с reply-клавиатурой
при удалении сообщения, которым она была отправлена. Снятие клавиатуры
описано только через `ReplyKeyboardRemove` или новую разметку — из чего
следует, что клавиатура привязана к чату, а не к сообщению, но прямого
утверждения нет. Ответ на `/start` приходит один раз при настройке; рисковать
клавиатурой ради одной строки в истории не стоит. Если на ноде окажется, что
клавиатура удаление переживает, включим и его в общий слот — это одна строка.

## Что меняется в коде

### 1. Очистка чата — `internal/tgbot`

- `PersistedState` (`bot.go:59`) получает поле `ServiceMessageID int`; в
  `TelegramBotConfig` — плоский ключ `service_message_id` рядом с
  `status_message_id` (`internal/server/telegram.go:40`), плюс строки в
  `botState()` и `saveState()`. Ноль означает «служебного нет», откат версии
  файл не бьёт — как и у прочих полей.
- `handleMessage` (`bot.go:893`) после обработки удаляет входящее:
  `client.DeleteMessage(ctx, m.Chat.ID, m.MessageID)`. Ошибка не критична —
  пишем в лог только то, что не является `IsMessageGone()`.
  Удаляем **только распознанные команды и нажатия кнопок в чате админа**.
  Произвольный текст админ пишет боту сам и осознанно — стирать его не наше
  дело; чужой чат не трогаем вовсе (`bot.go:902`).
- Новый метод `sendService(ctx, client, chatID, text, markup, silent)` —
  единственная точка отправки служебных сообщений: отправляет новое,
  запоминает id в состоянии, удаляет прежнее. Через него переводятся
  `commands.go:129,139,166,179,231` и `bot.go:338` (тестовое из панели).
  Отказ постороннему (`bot.go:903`) через слот **не** идёт: слот описывает
  чат админа, а туда пишется чужой чат — иначе одно сообщение затирало бы
  другое в другом диалоге.
- `deliver` (`bot.go:742`) при переотправке статуса вниз чата чистит слот:
  человек и так смотрит на свежий статус.
- Гонки: слот трогают горутина опроса и воркер. Пишем его под тем же
  `b.mu`, что и остальное состояние, и по тому же шаблону «под мьютексом
  снять `persist, state`, отпустить, вызвать» — как в `setMute`
  (`commands.go:213`). Сеть под мьютексом не держим.

### 2. Устойчивый разбор телеметрии — `internal/uplink`

- `ClassCount` получает `UnmarshalJSON`, принимающий **и** `total`, **и**
  `count`: панель читает `total`, а старые сборки движка могли отдавать иначе.
- Числовые поля, приходящие от движка, объявляются как `float64` там, где
  движок может отдать дробь (`uptime_seconds`,
  `process_started_at_epoch_secs`), и округляются при использовании. Это
  снимает и найденную поломку, и её повторение в будущем.
- `Summary` и `SystemInfo` разбираются **пополево** через
  `map[string]json.RawMessage`: одно кривое поле теряет только себя. Разбор
  остальных эндпоинтов не трогаем — они работают.
- `watcher.go:163,177,184` перестают молча глотать ошибку: причина пишется в
  лог, но **не чаще одного раза на новую причину** — иначе минутный опрос
  зальёт журнал. Повторяющаяся причина молчит до тех пор, пока не сменится.
- Мёртвое дублирующее поле `Status.UptimeSecs` (`verdict.go:112`) убирается:
  аптайм печатается из `/v1/system/info`.
- `topClasses` (`watcher.go:275`) сейчас режет список до 5 и 2 элементов
  (`watcher.go:166-167`). Раз показываем разбор целиком, отсечение уезжает в
  отрисовку — там оно зависит от остатка бюджета сообщения, а не от
  зашитого числа. Сортировка по убыванию остаётся.

### 3. Таблицы — `internal/tgbot/format.go`

Общая вспомогательная функция вместо трёх разных приёмов:

```go
// table собирает моноширинную таблицу: ширины колонок по факту, числа
// вправо, хвостовые пробелы срезаны.
func table(label string, head []string, align []bool, rows [][]string) string
```

`label` попадает в `<pre><code class="language-…">` — Telegram показывает
его в шапке блока вместо безымянного «копировать». Документация имя блока
не регламентирует (там сказано только про язык программирования), поэтому
хуже нынешнего не будет: не подхватится — останется «копировать».

Через неё переписываются:
- `writeDCs` (`format.go:340`) — колонки `DC · RTT · Писатели · Покрытие`,
  ровно как в панели (`MEQualitySection.tsx:26-49`). Отрицательные номера
  оставляем как есть: знак нигде в проекте не расшифровывается, а выдумывать
  расшифровку в боте — врать.
- `writeLoad` (`format.go:211`) — таблица из шести показателей и две таблицы
  разбора: «Ошибки соединений» и «Сбои рукопожатия», все классы.
- `writeProbes` (`format.go:567`) — уже почти такая, переходит на общую
  функцию и получает подпись «Зонды».

Строка про активные IP уходит в таблицу, так что вопрос заглавной буквы
снимается сам.

**Ловушка при смене разметки блока.** `closePre` (`format.go:386`) сейчас
считает буквально `<pre>` и дописывает `</pre>`. С подписью блок открывается
как `<pre><code class="…">`, поэтому счётчик перестанет совпадать, а
закрывать надо парой `</code></pre>`. Незакрытый тег — это 400 от Telegram и
отсутствие статуса вовсе, так что правку `closePre` делаем вместе с
подписями, а не после.

**Бюджет.** Сейчас сообщение при 20 зондах ~2600 знаков из 4096. Полная
таблица DC (12 строк) добавляет ~210, полная статистика — ~350. Выходит
~3160, запас ~900. Порядок блоков прежний: зонды рисуются последними и в
остаток бюджета (`writeProbes` уже так умеет), поэтому при полусотне зондов
ужимается список зондов, а не показатели. Дополнительно: если места мало,
таблицы разбора ошибок урезаются до пяти строк с итоговой строкой «прочие
— N», и только потом режется список зондов.

## Тесты

1. Удаление входящего: команда обработана — `deleteMessage` вызван с
   `message_id` входящего; ошибка удаления не роняет обработку команды.
2. Слот служебных: два служебных подряд — прежнее удалено, id нового
   сохранён; переотправка статуса чистит слот; ответ на `/start` в слот
   **не** попадает.
3. `ClassCount`: разбирается и `{"class":"x","total":5}`, и
   `{"class":"x","count":5}`.
4. Дробный `uptime_seconds` (`83220.47`) — сводка разбирается, остальные
   поля на месте. Это регрессионный тест на найденную поломку.
5. Кривое поле в сводке (например `configured_users:"много"`) — теряется
   только оно, соединения и классы остаются.
6. Подставной движок в `watcher_test.go` дополняется ответами
   `/v1/stats/summary` и `/v1/users`; проверяются `Connections`, `Users`,
   `ActiveIPs`, `TopBadClasses`, `HandshakeFails`.
7. Таблица DC: боевой снимок из `productionDCs` (12 DC, отрицательные
   номера, `rtt_ema_ms: null`) — колонки выровнены, DC без писателей
   показан, аварии нет.
8. Лимит: 50 зондов + полная статистика + 12 DC ≤ 4096 и все `<pre>`
   закрыты.
9. Ошибка телеметрии логируется один раз, а не каждую минуту.

10. **Сквозной тест «движок → сообщение»** — его отсутствие и есть корень
    всей истории. Сейчас разбор проверяется отдельно от отрисовки, а тесты
    формата подставляют числа руками (`format_test.go:702-703`), поэтому
    рисовали то, чего в бою никогда не приходило. Новый тест поднимает
    подставной движок с ответами всех пяти эндпоинтов, прогоняет `Watcher`
    и передаёт результат в `RenderStatus`, проверяя, что числа доехали до
    текста.

Существующие ожидания под старый формат строк — `"DC 1: 142 мс"` и
`"DC 3: —"` (`format_test.go:406,414`) — переписываются под таблицу.

## Проверка

Как в CI: `npm run build`, `gofmt -l`, `go vet`, `golangci-lint run`,
`go test -race ./...`, `go build`, кросс-сборки linux amd64/arm64.

На ноде после установки сборки `tg6`:
1. Нажать «📊 Статус» — нажатие исчезает из чата, статус переезжает вниз.
2. `/help`, затем `/mute` — в чате остаётся только последний служебный
   ответ, справка исчезла.
3. Проверить, что клавиатура под полем ввода на месте после всех удалений.
4. В сообщении появились все шесть показателей нагрузки, разбор ошибок и
   сбоев рукопожатия, версия движка и аптайм.
5. Таблица дата-центров выровнена, шапки блоков подписаны.
6. Перезапустить движок — приходит оповещение о перезапуске (сейчас оно
   не работает из-за той же поломки разбора).

Сборка `tg6` выпускается через ветку `tg-testing` и тег; ветка
`feat/telegram-availability-bot` в форк **не пушится**, чтобы PR не
обновлялся, — до отдельного слова.
