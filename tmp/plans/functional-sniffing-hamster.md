# Итерация 7: довести выбор бота до рабочего состояния

## Context

Живой прогон `install-fork.sh` на сервере показал четыре независимые поломки.
Три из них — мои ошибки в коде, четвёртая — недоделанная функция.

**Панель осталась старой.** Скрипт написал «Панель обновлена», а в браузере
прежний раздел без переключателя. Причина найдена: установщик панели заменяет
бинарник (`install -m 0755`), а затем делает `systemctl start` — не `restart`
(`mtproxyl-panel/install.sh:1195`). Служба уже работала, `start` для неё
пустышка, и в памяти остался прежний процесс со старым встроенным фронтендом.
Мой `install-fork.sh` при этом глушил весь вывод и печатал успех.

**И вдобавок ставился не тот релиз.** Установщик панели выбирает версию так:
берёт список релизов и делает `head -1` (`mtproxyl-panel/install.sh:823`).
GitHub отдаёт их не по дате, и первым в списке оказывается `…-tg9`, а не
`…-tg12`: сравнение выходит лексикографическим, где `tg9` больше `tg12`. То
есть все сборки, начиная с десятой, недостижимы в принципе. Переключатель в
`tg9` уже есть, так что сегодня это не главная причина, но следующий выпуск
не доехал бы вовсе.

**Контрольная сумма не проверялась.** Установщик просит
`<архив>.tar.gz.sha256`, а релиз содержит `<архив>.sha256` — суффикс `.tar.gz`
в workflow отрезается (`.github/workflows/mtproxyl-panel-release.yml:109`).
Получался 404 и честное «проверка пропущена». Та же ошибка в двух местах:
`install-alertbot.sh:164` и `lib/alertbot.sh:155`. Чинить надо установщики:
на имена в релизе завязан автообновлятор панели и его тест.

**Заголовок авторизации движка не находился.** Установщик перебирал
самодельный список путей, где настоящего — `/opt/mtproxyl/mtproxy/config.toml`
— просто нет: в списке `/opt/mtproxyl/config.toml`, без подкаталога. Режим
«супер эксперт» тут ни при чём, он использует тот же файл. Пока движок не
требует авторизации, это незаметно; как только потребует — бот бессрочно
покажет «Связь с Telegram — нет данных» и даже не поднимет тревогу.

**Переключателя ботов нет ни в меню, ни на деле.** Пункт «Телеграм бот» ведёт
сразу в меню того бота, который установлен (`lib/tui_alertbot.sh:139`), так что
второго человек не видит вовсе. А там, где переключатель есть — экран при двух
установленных ботах, — он ничего не переключает: пункты только открывают
подменю. Функции `take_over` зовутся исключительно из установки, `TGBOT_VARIANT`
читает один лишь TUI, а «Запустить» делает голый `systemctl start` без
`enable` — после перезагрузки поднимется не тот бот.

## Решения

| Вопрос | Решение |
|---|---|
| Панель после переустановки | `systemctl restart` вместо `start`; установщик форка показывает ошибку, а не глотает её |
| Контрольная сумма | Берём общий `checksums.txt`, как это делает установщик панели |
| Конфиг движка | Спрашиваем у MTProxyL: `mode --json` → поле `engine_config` |
| Меню «Телеграм бот» | Всегда экран выбора: оба бота, их состояние, пометка активного |
| Переключение | Отдельные доменные функции: активируют выбранного и останавливают другого |
| Панель | Та же кнопка «Сделать активным» рядом с переключателем |
| Видно ли, что стоит форк | Да: в шапке `by LiafanX · форк SkyDeaD`, имя берётся из `.repo` |

## Что меняется

### 1. Три починки установки

- `mtproxyl-panel/install.sh:1199` — `systemctl restart` вместо `start`. При
  первой установке это то же самое, при переустановке — единственный способ
  подменить работающий процесс.
- `mtproxyl-panel/install.sh:823` — выбор релиза. Сначала спрашиваем
  `/releases/latest`: GitHub сам считает его по дате публикации. Если тег
  оттуда без нужного префикса (у апстрима там релиз самого MTProxyL), падаем
  на прежний список, но сортируем его `sort -V`, а не берём первый попавшийся.
- `install-alertbot.sh` и `lib/alertbot.sh` — сверка суммы через
  `checksums.txt` по образцу `mtproxyl-panel/install.sh:848-866`: имя этого
  файла в релизе фиксировано и не зависит от того, как назван архив.
- `install-alertbot.sh` — путь к конфигу движка из
  `"$SCRIPT" mode --json` (поле `engine_config`), ровно как в
  `detect_from_mtproxyl` (`mtproxyl-panel/install.sh:711-740`). Установщик уже
  зовёт `availability status --json`, так что лишнего вызова не появится. Это
  же чинит режим реаниматора, где конфиг движка вообще чужой.
- `install-fork.sh` — при неудаче установки панели печатать последние строки
  её вывода, а не только «не удалось». Тихий успех на месте провала — худшее,
  что может сделать установщик.

### 2. Меню: всегда экран выбора — `lib/tui_alertbot.sh`

`tui_bot_menu` перестаёт угадывать и всегда показывает один экран:

```
► ТЕЛЕГРАМ БОТ

Активен: бот-сторож

[1]  Бот-администратор   не установлен
     управление прокси кнопками в чате

[2]  Бот-сторож          работает  ◄ активен
     тревоги: доступность и связь с дата-центрами

[3]  Сделать активным бота-администратора     (только когда установлены оба)

[0]  Назад
```

Пункты 1 и 2 открывают меню соответствующего бота (там же установка, если он
не поставлен) — то есть прежние `tui_tgbot_menu` и `tui_alertbot_menu` никуда
не деваются. Пункт 3 появляется, только когда переключать есть на что.

Образец, которому следуем, — `tui_target_menu` (`lib/tui_detect.sh:4-53`),
меню «Manager ⇄ Reanimator»: текущее состояние строкой в шапке, один пункт с
меняющейся подписью, а вся работа — в доменных функциях, не в TUI.

### 3. Переключение по-настоящему — `lib/alertbot.sh`, `lib/tgbot.sh`

Появляются две доменные функции по образцу `switch_to_manager_mode`
(`lib/detect.sh:1160`): идемпотентная проверка, затем работа.

```
bot_use_alert()  # выбранного: enable + restart; другого: disable + stop
bot_use_admin()  # зеркально
```

Существующие `alertbot_take_over` / `tgbot_take_over` становятся их частным
случаем — установка по-прежнему делает выбранного активным. Ключевое отличие
от нынешнего поведения: активируем через `enable`, а не только `start`, иначе
после перезагрузки сервера поднимется не тот бот.

Наружу — подкоманды `mtproxyl alertbot use` и `mtproxyl tgbot use`, чтобы
переключаться можно было и без меню.

### 4. Форк подписывает себя в шапке

Сейчас и оригинал, и форк выглядят одинаково: `MTProxyL v1.4.8 by LiafanX`.
Понять, что установлено, нельзя ни по одному экрану — а разница есть, и
поддержку человек будет просить у разных людей.

Подпись становится такой: `MTProxyL v1.4.8 by LiafanX · форк SkyDeaD`. Имя
берётся не из константы, а из `/opt/mtproxyl/.repo` (владелец до косой черты) —
тогда любой форк подпишется сам, а на официальной установке файла нет и строка
остаётся прежней, слово в слово.

Правится в четырёх местах, где шапка рисуется: `lib/utils.sh:394`
(`clear_screen`), `lib/tui_main.sh:15` (большой логотип), `lib/install.sh:8` и
`mtproxyl.sh:566`. Чтобы формулировка не разъехалась, все четыре зовут одну
новую функцию — `authorship_line`.

Панель себя подписывает уже сейчас: её версия у форка всегда выглядит как
`1.0.8-tg12`, официальная — как `1.0.8`. Отдельно добавим то же имя форка
рядом с версией на странице «Обновление».

### 5. Панель — кнопка рядом с переключателем

Переключатель на странице сейчас только меняет показанную форму. Рядом
появляется кнопка «Сделать активным», доступная, когда бот установлен и не
активен, и подпись, какой бот активен сейчас.

Панель делает это сама, без подкоманд форка — она обязана работать и поверх
официального MTProxyL:

- активировать сторожа: `systemctl enable --now mtproxyl-alertbot` плюс
  `mtproxyl tgbot stop` (право на это у панели уже есть);
- активировать администратора: `mtproxyl tgbot start` плюс
  `systemctl disable --now mtproxyl-alertbot`.

В `mtproxyl-panel/install.sh` добавляются недостающие права sudo на
`enable`/`disable` службы сторожа; ручка — `POST /api/alertbot/activate` и
`POST /api/tgbot/activate` рядом с существующими.

## Проверка

Как в CI: `gofmt -l`, `go vet`, `golangci-lint run`, `go test -race ./...` в
обоих модулях, `npm run build`, `sh -n`/`bash -n` по всем скриптам.

Тестами закрываются: разбор `checksums.txt` (правильная строка выбирается по
имени архива) и выбор активного бота в панели (какие команды зовутся для
каждого варианта).

Отдельно проверяется выбор тега — на живом списке релизов форка, где
лексикографический порядок даёт `tg9` вместо `tg12`.

Диагностика на ноде, чтобы отличить «не перезапустилось» от «не доехало»:
`/usr/local/bin/mtproxyl-panel version` — форковые сборки всегда называются
`1.0.8-tgN`, а голое `1.0.7` означает официальный бинарник, то есть замена
вообще не произошла.

На ноде — то, что сейчас сломано:
1. Повторный `install-fork.sh` — панель реально обновляется, в разделе
   «Телеграм-бот» появляется переключатель.
2. В выводе установщика — «контрольная сумма сошлась», а не «проверка
   пропущена».
3. `mtproxyl-alertbot config show` показывает непустой адрес API движка; если
   движок требует авторизации, связь с дата-центрами читается.
4. Меню «Телеграм бот» показывает обоих ботов и активного; переключение
   останавливает одного и запускает другого, `systemctl is-enabled` после
   переключения указывает на выбранного.
5. То же переключение из панели.
6. В шапке меню видно `by LiafanX · форк SkyDeaD`; после удаления
   `/opt/mtproxyl/.repo` и `mtproxyl update` подпись возвращается к обычной.
